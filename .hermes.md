# Verbigem Android — kontekst agenta (SUBPROJEKT)

Jesteś w `verbigem/android/` — subprojekcie **natywnej aplikacji Android**
(Kotlin + Jetpack Compose + llama.cpp NDK, silnik Hy-MT2-1.8B GGUF). Jeden z trzech
subprojektów ekosystemu Verbigem (obok `verbigem/webapp` i `verbigem/mini`)
w nadrzędnej strukturze `verbigem/` (zwykły folder, NIE repo git). Własne `.git`
+ remote `ihletru/verbigem_android.git`.

## ⚠️ Jesteś w subprojekcie — uważaj na sprzężenia
1. **Auto-update zależy od Mini:** `UpdateManager.kt` czyta
   `https://mini.verbigem.com/android/version.json` (generowane z
   `verbigem/mini/vite.config.ts` plugin `injectBuildId`). Jeśli Mini zmieni
   format/pola `version.json`, ten kod trzeba zaktualizować w lockstep.
   **NIE hardkoduj versionCode** — czytaj z version.json.
2. **APK ląduje w Mini:** build APK (`app/build/outputs/apk/debug/app-debug.apk`)
   → `verbigem/mini/dist/android/app-debug-vN.apk` → `npm run build` (mini) →
   `firebase deploy`. Zmiana ścieżki/nazwy APK w mini psuje kanał update'u.
3. **HARD (nie łam):** tylko silnik **Hy-MT2-1.8B GGUF** (NIE Hy-MT1.5).
   UI: TYLKO `stringResource(R.string.x)` we wszystkich 6 językach
   (en+pl+de+es+zh+tr). Hardkodowany tekst w composable/ViewModel = błąd.
